P0 verification and rendering evidence ledger

Frozen on 2026-09-02. These results intentionally separate three different questions: whether the engineering pipeline is internally coherent, whether an external paper's phenomenon can be reproduced from its locked data, whether a frozen ContextAdapt renderer retains real edit evidence, and whether that retention becomes real Agent success. The first three now have evidence. The fourth remains unearned.

4. Real-code renderer development and held-out evaluation

Commands:

npm run experiment:p0-real-code:dev
npm run experiment:p0-real-code:holdout

Evidence label: REAL_CODE_RETENTION_HOLDOUT New model calls: 0 Development: 23 tasks × 9 policies × 8 budgets = 1,656 cells Held out: 30 tasks × 9 policies × 8 budgets = 2,160 cells

The 30 held-out tasks span 12 repositories. The renderer sees only the issue and base-commit source; the gold patch is evaluator-only. The renderer, evaluator, split, source manifest, metrics, thresholds, and 10,000-draw repository-cluster bootstrap were fingerprinted in protocol-v3.json before the single held-out run.

The strict metric requires all three conditions: stay inside the source budget, preserve every exact issue line found in source, and retain at least one pre-edit line from every gold patch hunk.

Across the seven compressed budgets, ContextAdapt v3 improved strict retention over head/tail by +22.4 percentage points, repository-cluster bootstrap 95% CI [+2.4, +40.6]. Against lexical intent, the gain was only +7.1 points, 95% CI [-2.3, +17.9]: directionally positive but inconclusive. At the 40% checkpoint, ContextAdapt and lexical intent tied at 18/30, while v2 was 19/30. The development-set advantage therefore did not generalize cleanly.

The ablations sharpen the conclusion:

  • exact issue-evidence gating improved the compressed-curve strict metric over

ungated structural retrieval by +6.2 points, 95% CI [+1.1, +11.9], while edit hunk coverage was unchanged;

  • structural ranking versus ContextAdapt v2 was +4.3 points, 95% CI

[-4.6, +15.3], so its incremental held-out value is not established;

  • the evaluator-only anchor oracle exceeded ContextAdapt v3 by +42.9 points,

95% CI [+29.8, +55.8], exposing large remaining location headroom.

All 840 held-out monotonicity checks passed: a larger ContextAdapt budget never lost a previously retained anchor, hunk, issue line, or strict success. All 480 oracle-isolation checks passed, and there were zero delivered over-budget or missing-exact-evidence cells. An adversarial same-file traceback caused one held-out regression at 40% (and one offsetting improvement), confirming that untrusted location hints still need provenance-aware weighting.

The source ratio is not the whole bill. The fixed issue text was excluded from source allocation but included in the reported all-in estimate. All token numbers are characters divided by four, not provider tokenizer usage.

5. The deep conclusion

This experiment falsified the tempting strong story that “preserving the user request plus a clever structural slice is enough to know the shortest safe context.” It is not. ContextAdapt can now guarantee exact-evidence preservation, budget compliance, deterministic recovery, and monotonic escalation. It can also beat naive truncation on real code. But on the held-out set, 8 of 30 tasks still needed the full source before every gold hunk was retained, and the renderer itself could not know which eight without evaluator-only information.

That creates a clean separation:

  1. Proven now: ContextAdapt can build a safer, auditable context candidate

and substantially outperform position-only truncation.

  1. Not proven: the candidate is the shortest context that lets an Agent

finish the task.

  1. Required next: send the candidate to a real task Agent, run the real

verifier, escalate on failure, and count the failed attempt, recovery, reviewer, and larger-context retry. Only that closed loop can turn retention into a user-facing 200K/400K/1M recommendation.

6. Product claim still pending

The external coding-task layer has now been executed, but only as a within-file retention benchmark. The gold-touched file is preselected, so repository search is not tested. No Paritok model or task-Agent call was made.

IMPROVED remains unearned. It requires blinded, paired runs of the same Agent, task, Host state, and verifier across:

  1. always-largest + raw + verify-all;
  2. always-small + raw + native verification;
  3. ContextAdapt tier selection only;
  4. ContextAdapt tier + exact renderer + risk allocation + execution gate.

The primary acceptance target is not maximum compression. It is equal safety and completion versus the largest-context baseline at lower all-in cost, including review, verification, recovery, retries, and failed attempts.
